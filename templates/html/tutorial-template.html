现代微服务流式数据处理教程

在本篇实践教程中，我们将自底向上搭建一套具备高吞吐、背压控制与自愈机制的流式处理微服务。你将掌握契约编排、轻量响应式布局和优雅异常降级。

1. 架构流向与拓扑全景

系统整体采用解耦式发布-订阅架构。数据经过统一网关校验后，进入可靠的消息队列，随后由 worker 集群消费并写入分布式持久层。

2. 步骤一：创建项目配置与环境变量

我们使用声明式类型检查保证启动时能捕获所有配置遗漏，避免运行时抛出未捕获异常。

src/config/runtime.ts 
import { z } from 'zod';

export const ConfigSchema = z.object({
  KAFKA_BROKERS: z.string().default('localhost:9092'),
  DATABASE_URL: z.string().url(),
  RETRY_MAX_ATTEMPTS: z.coerce.number().min(1).default(3),
});

export type RuntimeConfig = z.infer<typeof ConfigSchema>;
⚠️
注意环境变量格式

如果使用容器网络，请确保 `KAFKA_BROKERS` 不填写 `127.0.0.1`，而应配置为宿主服务名 `kafka:9092`，以防止容器间跨网段隔离报错。

🔍 深度原理解析：背压（Backpressure）是如何生效的？ ▼

当消费者吞吐落后于生产者速率时，内存缓冲区将会膨胀。我们通过动态拉取批次窗口与反应式流契约，让 Consumer 自动调高拉取间距，促使上游减缓投递速率。
