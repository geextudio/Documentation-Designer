Agentic Engineering / VS Code 实战 / Copilot Chat 教程创作指南

在 VS Code 中使用 GitHub Copilot Chat 与 Agentic Engineering 构建现代技术教程指南

如何摆脱千篇一律、枯燥无味的纯文本教程？本教程通过实战演示，手把手带你在 VS Code 中利用 GitHub Copilot Chat 与本工作区固化的 Agentic Engineering 资产（AGENTS.md、13 个专业 Skills 及设计系统），一键生成具备现代化 SaaS 审美、优秀阅读体验、防横滚溢出并能开箱双击运行的工业级技术教程。

🎯 本篇学习目标
  • 理解 Copilot Chat 如何在上下文感知中自动加载并运用本地 Agentic 规则
  • 掌握通过精准提示词编排 tutorial-color-palette、tutorial-reading-experience 等 Skill 的技巧
  • 学会编写符合认知心理学的“四步动作节拍”教程正文与渐进式原理卡片
  • 实现同时输出标准 Markdown 与独立单文件 index.html 的双格式闭环交付

1. 核心理念与资产总览

传统 AI 编写教程往往存在代码无来源标识、宽屏行宽无限拉伸致眼疲劳、移动端代码把页面撑破、缺乏运行验证等痛点。而在本工程体系中，我们通过将工程经验具象化为一系列结构化文件，实现了对大模型生成过程的精密引导：

🎨 视觉与体验 Skill 族

包含 tutorial-color-palette（双模防眩光调色板）、tutorial-reading-experience（60-75ch黄金行宽与排版韵律）、tutorial-responsive-layout（多端响应与移动触控）等。

📐 教学与架构 Skill 族

包含 learning-path-engine（章节路径与认知节奏）、documentation-designer（四步节拍与双交付架构）、code-snippet-enhancer 与 diagram-architect 等。

2. 协同流水线拓扑

在 VS Code 中通过 GitHub Copilot Chat 发出指令后，Agent 内部会依序启动以下四个阶段的协同流水线：

3. VS Code 实战四步操作法

按照以下四步法，在 VS Code 中无缝调动 Agentic Engineering 体系：

步骤一：打开工作区并注入上下文引用

在 VS Code 中通过快捷键 Ctrl+Shift+I 或 Cmd+Shift+I 打开 GitHub Copilot Chat。在提问框中，可以通过引用当前工作区文件确保 Agent 获取最新规则。

步骤二：选用结构化创作提示词 (Prompt)

输入包含明确 Skill 指引和交付要求的结构化提示词。例如明确要求“四步动作节拍”、“黄金行宽 60-75ch”、“明暗低眩光”以及“输出独立完整 index.html”。

Copilot Chat Input Prompt 
# 发送给 GitHub Copilot Chat 的规范提示词
请基于本工作区的 Agentic Engineering 体系（严格遵循 AGENTS.md、docs/design-system.md 以及相关 Skills），为我生成关于【主题】的现代技术教程。

要求：
1. 教学设计：依据 learning-path-engine 和 documentation-designer，开篇包含学习目标与预计耗时，正文采用四步动作节拍，次要技术细节使用折叠卡片封装。
2. 视觉与排版：依据 tutorial-color-palette 与 tutorial-reading-experience，配置低眩光明暗双模底色，行宽限制在 60-75ch。
3. 交互与多端：依据 code-snippet-enhancer 和 tutorial-responsive-layout，包含路径标注、复制按钮与防横滚隔离。
4. 双格式输出：同时提供规范 Markdown 与单文件独立 index.html。
💡
技巧：利用 VS Code # 符号直接指定上下文

在 Copilot Chat 输入框中键入 #file:AGENTS.md 或 #file:docs/design-system.md，能够强制让 Copilot 读取规则文件的具体参数，确保生成的调色板与行宽数值 100% 精确吻合。

步骤三：正文落地的“四步动作节拍”法则

生成教程正文时，检查 AI 是否严格遵循了“四步动作节拍”。每一个操作小节必须形成“意图动词 $\rightarrow$ 原理简析 $\rightarrow$ 执行代码 $\rightarrow$ 终端结果”的闭环回路：

$ 执行生成的教程验证脚本并观察回显
✔ [Step 1] Environment variables schema parsed.
✔ [Step 2] Worker connection established.
ℹ [Step 3] Output buffer backpressure threshold verified (5000 items/s).
✨ All steps executed successfully.

步骤四：一键写入文件并即时双击预览

Copilot 生成代码后，直接让其利用文件创建能力将结果保存至工作区（如保存为 my-tutorial.md 与 my-tutorial.html）。对于 HTML 文件，直接在文件管理器中双击即可在浏览器中打开，零编译环境依赖体验现代排版与交互。

4. 场景化 Prompt 模版库

针对不同的创作阶段，可直接选用以下经过调优的提示词模版：

📋 模板 A：从零新建完整技术教程（标准生成） ▼ 
请充当 documentation-designer 专家，基于当前项目的 AGENTS.md 规则，为我编写一篇关于【主题】的实战教程。
- 主体结构：前置依赖 -> 学习目标 -> 架构拓扑(Mermaid) -> 步骤1..N(四步法) -> 验证回显 -> 避坑指南。
- 视觉与交互：参考 tutorial-color-palette 与 tutorial-reading-experience 规范，配置低眩光双模样式与 60-75ch 黄金行宽。
- 交付方式：先输出 Markdown 格式，然后将 HTML 版本保存到当前工作区。
✨ 模板 B：旧教程翻新与体验升级（重构优化） ▼ 
请调用 tutorial-ui-optimizer、tutorial-reading-experience 和 accessibility-reviewer，对我选中的旧教程文档进行重构：
1. 重新规划行距与标题锚点滚动偏移；
2. 为所有代码片段补充文件名标签、一键复制及终端预期输出回显；
3. 将散乱的注意点重构为标准的 GitHub Admonition 语法；
4. 基于 templates/html/tutorial-template.html 输出可离线浏览的独立 index.html。

5. 双格式产物交付标准

基于本体系生成的教程产物必须实现“双轨并行”，满足不同发布渠道的诉求：

格式类型 主要应用渠道 特色与优势 规范要求
Markdown (.md) Git 仓库、GitHub Wiki、VitePress、Docusaurus 纯文本轻量、易版本控制、原生支持 Diff 与 PR 审核 遵循 GitHub Admonitions 提示框语法；代码块标注文件名
独立单文件 (.html) 本地双击离线阅读、产品内置帮助页、邮件/微信分发 零编译环境依赖、内置暗黑切换、阅读进度条、一键复制 基于 tutorial-template.html；集成 Mermaid.js 与 Tailwind 预设

6. 质量验收与打分表 (0–100 Rubric)

生成完毕后，可以参照工作区内置的评分量表进行核验（满分 100 分，90 分以上为企业级金牌标准）：

20
视觉美学与配色调色板 (20分)

浅色 #F8FAFC 与深色 #0B0F19 低眩光设计；文字对比度 $\ge 4.5:1$；代码语法主题与正文背景协调。

20
阅读体验与排版韵律 (20分)

正文行宽锁定在 60–75ch；行高 1.75–1.8；标题预留 5rem 滚动防遮挡边距；包含阅读进度条。

20
教学架构与四步节奏 (20分)

具备明确的学习目标与预估时间；每步遵循“动词目标 -> 简析 -> 代码 -> 终端回显”；进阶细节折叠。

20
多屏幕适配与横滚隔离 (20分)

桌面三栏优雅折叠为移动端单栏；代码与宽表格横滚不破视口；触控热区 $\ge 44\text{px}$ 并适配安全区。

20
技术准确性与双格式交付 (20分)

同时提供语义化 Markdown 与独立可运行 HTML；无死链，代码无语法错误，双击即可无障碍演示。
